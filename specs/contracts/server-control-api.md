# Server Control local API

Status: implemented for the local-only administration service.

The API is bound to `127.0.0.1`. It is not a public Edge/server interface; Edge
and the server continue to communicate only through Box.

## Authentication

The complete listener, including the UI, static assets, admin API, thumbnails
and video streams, requires exactly one syntactically valid HTTP Basic
`Authorization` header. Credentials come from the mandatory process environment
variables `BEARVISION_ADMIN_USERNAME` and `BEARVISION_ADMIN_PASSWORD`. Invalid
configuration stops Server Control before the Python worker or either HTTP
listener starts. The credentials are not passed to Python processes.

Missing, invalid or incorrect credentials return:

- status `401`;
- `WWW-Authenticate: Basic realm="BearVision Server Control", charset="UTF-8"`;
- `Cache-Control: no-store`;
- JSON body `{"error":"authentication required"}`.

Every endpoint below can return this `401`. Successful response bodies, status
codes and request formats are otherwise unchanged. The separate Android API on
port `4321` does not use these administrator credentials.

## Read endpoints

- `GET /api/summary` returns worker state and queue counts.
- `GET /api/jobs` accepts `page`, `pageSize`, `status`, `query` and `userId`.
- `GET /api/jobs/<job-id>` returns manifest and assignment evidence.
- `GET /api/jobs/<job-id>/thumbnail` returns a Python-generated JPEG.
- `GET /api/jobs/<job-id>/video` streams the verified cached video and supports
  one HTTP byte range.
- `GET /api/users` accepts `page`, `pageSize` and `query`.
- `GET /api/beartags` returns tags and their assignment history.

## Mutations

- `POST /api/users`
- `POST /api/users/<user-uuid>/email` (retained for compatibility)
- `PUT /api/users/<user-uuid>` edits `displayName` and `email` without changing
  the UUID and records `reason`, before/after values and timestamp in registry audit.
- `POST /api/beartags`
- `POST /api/assignments/validate`
- `POST /api/assignments`
- `POST /api/assignments/history/preview` validates replacement intervals and
  returns every affected clip with current/expected status and user plus
  `changed`, `unchanged` and `unresolved` counts.
- `POST /api/assignments/history/apply` stores the history change and audit entry,
  then recalculates the same impact set as one operation. `overrideManualAssignments`
  defaults to `false`.
- `POST /api/jobs/<job-id>/assignment` manually assigns a processed or unresolved
  clip with `userId` and `reason`.
- `POST /api/jobs/<job-id>/requeue`

Assignment IDs are generated by Python when the UI omits one. Validation and
creation use the same authoritative registry rules. All date-time values cross
the process boundary as UTC ISO 8601 strings.

## Process boundary

Node does not inspect Box, generate thumbnails, validate assignments or derive
job presentation data. Each route sends one versioned JSON command envelope to
the `bearvision.server.cli execute` seam over stdin. Python owns command
validation, dispatch and typed read models, returning JSON or a path inside its
verified media cache. Node only performs HTTP presentation and range streaming.
## Correction data

BearTag history changes replace one existing interval with one or more contiguous
intervals. Replacements must cover the original interval exactly, use the same
BearTag, and contain neither overlap nor gaps; prior values remain in the
registry `auditTrail` (registry `schemaVersion: 3`).

New result files use `schemaVersion: 3`. They add `assignmentSource` and, for a
manual assignment, `manuallyAssignedAt`, `replacedUserId` and `manualReason`.
Python continues to read existing schema-version-2 result and registry files.
Recalculation rewrites only `result.json` and moves the intact job package to its
new logical queue location.
